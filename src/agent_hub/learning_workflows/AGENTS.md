# 单用户工作流维护规则

本指南继承仓库根 AGENTS.md，仅作用于本目录。先读 docs/learning-workflows.md 与当前 catalog.json，核对 Git 状态；不读取用户实际数据库、token 或登录文件来代替 fixture。

## 所有权与当前版本

- catalog.json 是默认唯一声明源；catalog.py 负责声明/输入校验，store.py 负责事务与运行历史，maintenance.py 负责本地清理与恢复，cli.py/server.py 负责入口和协议。输入字段只在声明中维护。
- 每个流程只暴露一个当前可执行版本；不增加多版本兼容矩阵、旧命令别名或旧库迁移。调整现有定义必须增加版本号；相同身份内容不可变是历史约束，不是兼容承诺。
- 目录摘要只证明声明内容，不证明 Forge 实现、消费 pin、发布制品或真实平台已验收。Hub 不复制 Forge runner/builder，也不修改其生成契约。
- HTTP 不接受模型生成的代码、任意 URL、shell、Git、发布或在线编辑声明。模型界面/动作只能使用已声明能力，不能直接取得工程执行权限。

## 本地运行与动作效果

| 动作 | 效果与约束 |
| --- | --- |
| inspect | SQLite 只读，不创建库、不启用目录、不结算过期 |
| serve | POSIX 本机单实例写锁，回环监听；端口绑定成功后才启用声明 |
| maintain | 离线持有同一写锁；结算超时、清理、到期备份；不启用默认声明 |
| restore | 只写不存在的新目标，原子安装；不覆盖原库/快照，恢复前清理并终止未完成运行 |
| GET runs | 会结算过期；不得描述为无写入审计 |

- 新目录启用必须在同一写事务内安装声明、结算旧未完成任务、撤销旧租约/注册并切换当前目录。相同目录重启不中断；非法声明/同版本冲突整体回滚。
- 升级终止用 cancelled 终态和明确“升级终止”原因表示；旧定义、输入和事件保留，迟到回报不能改写历史。执行端确认停止、控制面终态、外部效果撤销是三件事。
- 重试默认选当前启用版，创建独立运行与 retryOf 关联。单用户允许新注册执行端重试旧身份任务，但仍须校验同流程、原失败/取消终态和当前输入；不猜测参数迁移。
- 相同 requestKey 的重传返回原运行，不当作新版重试。旧数据格式明确拒绝，不删除旧文件，不自动导入旧运行。

## 持久化与失败

- 默认持久目录由 XDG_STATE_HOME 或用户状态目录解析；数据库、备份与临时令牌权限 0600，不能进入 Git、源码索引或模型请求。模型会话默认不落盘，脱敏证据显式保存。
- 默认终态结束后保留 30 天，关联删除输入/结果/事件；每日 SQLite 一致性快照轮换 7 份。不直接复制活跃库单文件，不在备份失败时更新成功时间。
- restore 先校验、清理，再提供查询/领取；备份中的未完成任务不可自动重放。滚动备份可暂存过期内容，不承诺第 30 天所有磁盘副本物理清除。
- 保留鉴权、来源校验、租约、幂等键、输入/输出边界和进程锁。单用户/接受破坏性修改不意味着可以去掉这些运行正确性约束。
- 服务运行期维护与离线每日调度分别报告；没有安装并实测系统调度时，不能写成全天候自动备份已完成。错误必须有非零退出或状态诊断。

## 验证与交付

使用 `./agent maintenance-test --profile workflow`，固定临时状态、随机回环端口。涉及事务、备份/恢复、CLI 时保留对应 fixture，不调用用户服务、外部模型或远端业务接口。

根命令/观察配置变化补 `./agent maintenance-test --profile maintenance`；规则继承变化补 `PYTHONPATH=src .venv/bin/python -m unittest tests.test_rule_entrypoints`。Python 缓存通过 PYTHONDONTWRITEBYTECODE 或仓库外路径隔离。

提交前核对精确路径与暂存差异。代码/规则、已提交、已推送、已启用、主机验收分别记录；不得因 Hub fixture 通过将 Forge v1 消费限制或未安装的调度标成完成。当前任务已经授权的改动、提交和推送直接执行，不重复索取批准。
